## 二、根因与修复（不是逐个补，而是改生成机制）

### 2.1 操作日志筛选"形同虚设"

**根因**：上一轮为"增强体验"注入的 `ui-enhance.js` 里有一套"即时筛选"，它只在**当前页 10 条**数据里过滤，还把控件插进了真正的筛选条，把服务端筛选挤到视觉之外。后端筛选一直是好的（12827 条日志可按模块/结果/关键词正常过滤），坏在前端把真筛选盖住了。

**修复**：整体删除 `ui-enhance.js` 中的 `applyFilter` / `buildChips`（假筛选与假筛选条），筛选一律走服务端 `module` / `result` / `keyword` 参数。

**验证**：抓包确认请求带 `?module=登录&result=&keyword=`，结果集真实变化；筛选区已无"只在当前页过滤"的注入控件。

### 2.2 登录界面选角色没用

**根因**：角色按钮只改了前端本地变量，从未参与登录请求与后端校验。

**修复**：`LoginDTO` 增加 `expectedRole`；`AuthService` 在密码校验通过后比对账号真实角色，不一致直接拒绝并回传可读文案。

**验证**：用工号角色选"农户/合作社"登录 → 被拒，提示"该账号不是「农户/合作社」，请切换到正确角色，或取消角色选择后登录"；角色一致 → 正常进入管理端。

### 2.3 弹窗"固定不居中"

**根因**：全局样式给 `.page` 加了 `pageIn` 入场动画，动画用 `transform: translateY(...)` 且 `animation-fill-mode: both`，动画结束后计算样式仍保留 `matrix(...)`。**有 transform 的祖先会成为 `position: fixed` 的包含块**，于是 Element Plus 的 fixed 遮罩不再以视口定位，而是被钉在内容区左上角（实测横偏 104px、纵偏 98px）。

**修复**：改全局 CSS——入场动画只用 `opacity`（`fadeIn`），彻底移除 `transform`，并统一 dialog 居中规则。一处修复，全系统 20+ 个弹窗同时生效，不是逐个改。

**验证**：脚本打开多个弹窗实测中心点偏差 `dx=0 / dy=0`，不溢出视口，页面滚动后仍居中。

### 2.4 按钮"点了没反应"（导出 / 模板 / 报告 / 打印 / 已读）

**根因**：多处 `@click` 只弹了个 `ElMessage.success('导出成功')`，或调用了不存在的函数。

**修复**：新增 `utils/export.js`（`downloadCsv` 生成真实 Blob + `exportTableDom` 从 DOM 抽取表格数据），逐个接上真实行为：看板运营报表、农户名册、食堂名册、农产品导入模板、操作日志导出、溯源报告下载、质检照片选择与预览、`window.print()` 打印、消息已读 `localStorage` 持久化。

**验证**：点击后 Playwright 捕获到真实下载（文件名 + 字节数），刷新后"全部已读"仍生效。

## 三、跨角色实时反馈（本轮重点能力）

### 3.1 链路

```
业务写操作（AOP 统一切面）
   → sys_event 表（定向 target_user_id + target_roles）
   → SSE 推送 /api/common/events/stream（断线自动降级为轮询）
   → 前端 27 个页面静默自动刷新
```

- 后端新增：`SysEvent` / `SysEventMapper` / `RealtimeService`（写事件 + 可见性过滤）/ `RealtimeController` / `config/RealtimeAspect`（拦截写操作自动落事件，业务代码零侵入）。
- 前端新增：`utils/realtime.js`（SSE 优先、断线转轮询、收到 `ACCOUNT_DISABLED` 立即跳登录）、`utils/useAutoRefresh.js`（`document.hidden`、弹窗遮罩、输入中自动延后，且**不显示整页 loading**）。
- 顶栏新增通知中心：未读角标、实时/轮询状态灯、最近动态列表。

### 3.2 关键场景实测

## 六、补充修复（2026-11-10 16:55 追加）

### 6.1 管理员侧栏看不到「数据看板」

**现象**：登录后侧栏只有基础档案 / 业务监管 / 系统管理三组，第一组「概览」连同其中的「数据看板」整组消失，只能手输 `/admin/dashboard` 才进得去。

**根因（两层）**：
1. **数据层**：`sys_role_menu` 里管理员角色授权了子菜单 `10`（数据看板），却漏配父菜单 `1`（概览）。其余三个角色的父菜单都配了，所以只有管理员缺一组。
2. **代码层（真正的坑）**：`AuthService.menus()` 建树时只遍历 `parentId == 0` 的**已授权**节点作为分组，再回挂子节点。父节点没授权 → 分组不存在 → 它下面**所有子菜单被静默丢弃**，不报错、不打日志。

**修复**：
- 代码层兜底：`menus()` 先算出"有授权子菜单但父节点未授权"的父 id，自动把这些父节点补进结果集再建树，并打一条 `log.info`。以后任何角色漏配父菜单都不会再静默丢菜单。
- 数据层：`sys_role_menu` 补 `(1,1)`；`db/02_data.sql` 同步补上，保证重新初始化也不会再缺。

**验证**（`tools/check_menu.cjs`，13 项全过）：
- 接口层：四个角色菜单项逐一比对应有清单，**0 缺失、0 空分组**（管理员 11 项 / 农户 6 项 / 采购员 7 项 / 质检员 5 项）。
- 兜底能力反向验证：手工删掉 `(1,1)` 后再次请求，菜单仍然完整返回「概览 → 数据看板」，证明兜底真的生效，不是只靠补数据；验证完已把数据补回。
- 界面层：管理员登录后侧栏真的渲染出「数据看板」并高亮，链接指向 `/admin/dashboard`，点击进入「运营总览」，全程 0 控制台错误。
- 目检截图：`I-侧栏数据看板.png`。

> 上轮 27 项验收为什么没抓到：看板检查是直接 `goto('/admin/dashboard')`，只验证了"页面能打开"，没验证"入口在侧栏可见"。**能打开 ≠ 有入口**，这是验收口径的盲区，已补进菜单检查脚本。

### 6.2 同时登录多个角色：提示「无权访问该资源」，随后数据全空

**现象**：同一浏览器开多个标签页分别登录不同角色后，先登录的标签页突然报"无权访问该资源"，表格变空；刷新还可能被丢到**另一个角色的首页**。

**根因**：会话（token / 用户 / 菜单）存在 **localStorage**，它在同一域名下**全标签页共享**。后登录的角色会把 token 覆盖成自己的，于是：
1. 先登录的标签页带着"别人的身份"去请求自己的接口 → 后端按 token 里的角色判权 → `403 无权访问该资源`（已用 curl 实证：管理员 token 请求 `/api/farmer/sources` 返回 `{"code":403,"message":"无权访问该资源"}`）。
2. 刷新时路由守卫用这个串过来的身份复核 → 当前路由不在该角色菜单里 → `return store.home` → 被重定向到另一个角色的首页。"数据全没了"是两个原因叠加的观感。

**修复**：会话改为**按标签页隔离**。
- 新增 `utils/session.js`，全站唯一的会话读写入口，落在 **sessionStorage**（每标签一身份、同标签刷新保留）。
- `store/user.js`、`api/request.js`、`utils/realtime.js`（SSE 与轮询）、`utils/useAutoRefresh.js` 全部改走该入口，不再有任何地方直读 `localStorage` 的会话键。
- 提供一次性迁移：把旧 localStorage 里的会话搬到当前标签页并**删除污染源**，老用户刷新不掉线。
- 顺带修掉一个由 401 逻辑引入的回归：登录页输错账号时不再只清状态不提示（无登录态时只提示、不清状态、不跳路由；并发 401 只提示一次）。
- 文案如实：`localStorage` 里只保留账号名（"记住账号"）与外观偏好，登录页明确写"可在多个标签页各登录一个角色，互不影响"。

**验证**（`tools/multitab_check.cjs`，16 项全过）：
- 三个真实标签页分别登录 农户 / 管理员 / 质检员，三者持有**各自不同的令牌**，`localStorage` 里**没有任何会话键**。
- 农户标签切页、刷新后仍是农户，**0 次 403**、无"无权访问"提示、表格仍有 10 行数据。
- 管理员标签刷新后仍是管理员；另一标签"退出登录"不影响它。
- 三标签全程 **0 控制台错误**。截图：`J-多标签-农户仍在.png`、`J-多标签-管理员.png`。

### 6.3 顺带查出：KPI 卡片数字恒为 0（农户货源页等）

**现象**（排查 6.2 时目检截图发现）：农户货源页"在售货源 / 累计发布 / 本月成交 / 已售罄"四个 KPI 全显示 0，而同一行文字写着"共 24 条 · 在售 7"，表格也有 10 行数据。

**根因**：注入层的"数字滚动"动画用 `el.textContent = ...` 做逐帧动画。`textContent` 赋值会**移除元素的所有子节点**（包括 Vue 管理的文本节点和 `<small>` 后缀），然后再造纯文本。等接口数据到达、Vue 去更新那个文本节点时，它已经游离在 DOM 之外了——页面上的数字就永久停在首屏值（通常是 0）。接口本身是对的（`stats.onSale = 7`），错在注入层和框架抢同一批 DOM。

**修复**：`animateNumbers` 改为只写**文本节点的 `nodeValue`**，不重建子节点；并加了 `textNode.isConnected` 守卫，节点被卸载就立即停手。视觉增益保留，数据更新恢复。

**验证**：农户货源 KPI 变为 `7 / 24 / 56 / 1`，与接口一致。新增 `tools/probe_kpi_all.cjs` 巡检全部 **14 个用 StatCard 的页面**：KPI 与表格数据比对，**0 个可疑页**（KPI 全 0 但有数据的页面数 = 0）。

**顺带修文案**：结算页 KPI 的"已结算"实际口径是**本月**已结算（后端带本月过滤），标签改为"本月已结算"，避免把"本月 0 笔"读成"从来没结算过"（库里实际有 286 笔历史已结算）。

## 七、已知边界（如实说明，不藏）

1. **实时依赖 SSE 长连接**：浏览器或代理不支持 SSE 时自动降级为 8 秒轮询，此时最迟 8 秒可见，非瞬时。
2. **消息已读状态存 localStorage**：换浏览器/清缓存会回到未读，属服务端未建已读表的设计取舍；如需跨端一致，需加 `sys_message_read` 表。
3. **导出走前端 CSV**：当前数据量（万级日志）没问题，量级再上一档应改为服务端流式导出。
4. **演示数据日期**：`price_history` 最新为 2026-10-25，看板锚定该日期，因此图中"最近"指该日而非今天。
5. **会话按标签页隔离后，关闭浏览器需要重新登录**：这是"多角色并存"的代价，`sessionStorage` 不跨浏览器会话。原"记住我（7 天免登录）"的文案已据实改为"记住账号（下次自动填写）"，避免承诺做不到的事；若确实需要免登录，应改用"刷新令牌 + 服务端设备列表"的方案，不能靠把令牌塞回 localStorage。
6. **同一标签页内切换角色需要先退出**：标签页只保存一个身份，这是隔离的必然结果（想同时用两个角色就开两个标签页）。
