# 易用性诊断与优化报告

> 项目：农产品直供溯源与结算管理系统（Spring Boot 3.2.5 + Vue 3 + MySQL 9.6）
> 日期：2026-11-10　范围：全站 29 个页面、4 个角色
> 起因：「我试着用了一遍，感觉很难用，但又说不出来为什么」

---

## 一、先把「说不出为什么」变成可数的东西

用户说不清，通常不是因为问题少，而是因为**每个问题单独看都不致命**：字小一点、多一排筛选、按钮藏在图标后面、数字对不上……单个都能忍，叠在一起就变成「用着别扭」。

所以第一件事不是改，是**测**。我写了一个量化探针 `tools/ux_probe.cjs`，用真实浏览器按 4 个角色登录取证 29 个页面，采 12 类客观指标：首屏是否有主操作、表格列数、是否横向溢出、字号分布、一屏几屏高、筛选条占比、是否出现英文状态码、空状态、控制台报错。

第一次跑出来的结果，基本解释了「难用」：

| 指标 | 整改前（29 页） |
|---|---|
| 小于 12px 的文字 | **2555 处，平均每页 88 处** |
| 每页小字超过 20 处的页面 | **29 / 29（全部）** |
| 表格列数 > 8 的页面 | 7 个（最多 11 列） |
| 同一维度有两套筛选入口的页面 | 6 个 |
| 顶栏常驻控件 | 8 个（其中 3 个是设置项） |
| 信用分明细里完全相同的记录 | 19 / 19 行 |

其中**字号**是最普遍、也最容易被说成「就是感觉累」的那一条：表头 11px、表格正文 12.5px、状态标签 10.5px、卡片标签 11.5px。中文在 12px 以下辨识度会明显下降，而这张表要天天看。

---

## 二、七条根因（都在机制层，不是逐页补丁）

### 1. 全站没有排版比例尺

字号全部散落硬编码，`11 / 11.5 / 12 / 12.5 / 13 / 13.5` 六个近似值混用，380 处写死在 31 个文件里。没有比例尺，就只能一处一处凭手感调，最后谁都不统一。

**修法**：在 `tokens.css` 建 7 档令牌 `--fs-2xs … --fs-display`（最小 12px，`--fs-2xs` 只允许用于纯装饰），再用 codemod（`tools/codemod_fontsize.py`）把 380 处裸 px 全量映射过去，并把 Element Plus 的 `--el-font-size-*` 也接上同一套。顺带把表头颜色从 `--muted` 提到 `--ink-2`——表头本来就该比数据更清楚，而不是更模糊。

### 2. 顶栏的视觉权重是反的

最常用的是「待办」「实时动态」，但它们是无文字的小图标，要 hover 才知道是什么；一年点一次的「外观 · 浅色」下拉和「弱动效」复选框，却常驻在最显眼的右侧。

**修法**：待办、动态改成「图标 + 文字 + 数字」的按钮；外观三档、弱动效、账号信息收进用户菜单；去掉顶栏时钟（信息价值趋零，还每秒重渲染）。另外 `⌘K` 在 Windows 上按不出来，改成按平台显示 `Ctrl K`。

### 3. 同一维度摆了两套筛选入口

6 个页面同时有「带数量的快捷标签」和「同维度的下拉框」：

- 订单监管：状态标签 + 状态下拉（下拉里还有 5 个状态在标签里选不到）
- 农产品档案：品类标签 + 品类下拉
- 农户管理：类型标签 + 类型下拉（标签里还混了「待审核」这个状态维度）
- 农户订单 / 采购订单 / 需求管理：同上

用户不知道该点哪一个，点了发现两边联动又觉得「我点了个啥」。

**修法**：统一规则——**状态/类型/品类走带数量的分段控件，其它条件走筛选条下拉，一个维度只留一个入口**。去掉重复的 6 处下拉；把分段控件补全到能覆盖全部取值（例如农户订单从 5 个补到 8 个），保证去重不丢能力。再把「待审核」从类型标签里拿出来，改成点统计卡直接筛——数字从装饰变成动作。

### 4. 图表口径会骗人

- 看板趋势图把 11 月（只有 1-10 日）和整月并列，末尾一条断崖，第一眼像「业务崩了」；
- 农户工作台用「万元」做单位，柱子标签是 0.07 / 0.18，读起来要在脑子里换算；
- 三张窄卡下面各有一条进度条，但分母是自己编的（近 6 月 / 累计），没有任何目标值；
- 「本月收入 ¥0.00」旁边挂着「较上月 +16.6%」——那个 16.6% 其实是 10 月 vs 9 月。

**修法**：趋势图只画完整月份，当月单独用文字给出；单位统一为「元」并对齐千分位；删掉没有分母的进度条；环比改成和「本月收入」同源，本月为 0 时不显示涨跌。

### 5. 深色模式有一半文字是瞎的

样式块里写死了 `#15803d`（53 处）、`#1b2a24`（47 处）这类深绿近黑色，绕过令牌就不会随明度切换。深色模式下「我的在售货源」的产品名、「信用分明细」的变动原因几乎看不见。

**修法**：新增语义浅底令牌 `--ok-soft / --warn-soft / --danger-soft / --info-soft`，用 codemod（`tools/codemod_colors.py`）替换样式块内 309 处硬编码色。**只改 `<style>` 不改 `<script>`**——图表 option 里传 `var(--accent)` ECharts 解析不了，那类必须走新的 `utils/theme.js` 在运行时读计算值。

### 6. 信用分明细的账本是假的

251 条记录里 **248 条是 `90 → +1 → 91`**，而且 `create_time` 与 `id` 不同序。用户滚到「信用分明细」看到 19 行一模一样，会立刻判断这系统是编的；而农户当前 92 分、明细加总 +19，两个数对不上。

**修法**：按每位农户的当前信用分**倒推**重建成连贯账本（每条 `before == 上一条 after`，最终分与 `farmer.credit_score` 一致），时间递增、原因按正负分池。同时把查询从 `order by id` 改成 `order by create_time`（日志列表同样问题，一并改）。修正脚本 `db/fix_credit_ledger.sql` 已并入 `db/02_data.sql`，换机器重装不会退回假数据。

### 7. 卡片会被拉伸，空白像加载失败

农户工作台右侧「待处理订单」只有 1 条，却被拉伸到和左边图表一样高，留下 200px 空白。`grid` 默认 `stretch` 造成的。

**修法**：`align-items: start`，按内容高度排列。

## 六、已知边界（如实说明）

1. **没有做「点几次能完成一件事」的路径测量**。这次测的是页面级指标（字号、列数、入口重复、溢出）。任务级点击深度需要埋点或逐步脚本，本轮没做。
2. **行内操作仍是文字链**。部分表格每行 3 个链接（查看/编辑/停用），密度偏高。改成「主操作 + 更多」需要逐页改模板，涉及 20+ 页面，这轮只统一了字号与颜色权重，没有再动结构。
3. **侧栏分组编号（01–11）保留**。它是纯装饰，不承载信息，删掉视觉更干净，但也确实不影响可用性，优先让给了上面几条。
4. **深色模式只做了目检 + 令牌替换**，没有做全量对比度数值审计（之前的 `ui_contrast_audit.cjs` 可以补跑）。
5. **`db/02_data.sql` 里的 `DROP TABLE` 依然存在**，只能用于空库初始化。
6. 演示数据的时间戳仍是 2026-05～2026-10/11 的历史区间，看板的「最近」指的是库内最新日期，不是今天。
