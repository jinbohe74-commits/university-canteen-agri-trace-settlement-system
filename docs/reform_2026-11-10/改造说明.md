# 第四轮整改说明：行情自选 / 界面残留 / 质检到入库真实性 / 实时地图

日期：2026-11-10
面向反馈：

> 「数据看板里面的行情价格永远就这两个类型，不能自己选择；还有'复制'这个字样在前端界面没处理好；质检之后的流程都太随便了，随便点点就行，完全感觉不到和实际情况有任何关系；配送过程中希望能配一个动态实时地图。」

这份文档记录**每条反馈的根因取证、改法、验证证据、以及还没解决的边界**。延续 `docs/procurement_2026-11-10/改造说明.md` 的原则：先查库/查 DOM，再动手，不按感觉改。

---

## 一、四项反馈的根因

| 反馈 | 取证到的根因 | 不是什么 |
| --- | --- | --- |
| 行情只能看两个品种 | `StatMapper.topPriceProducts()` 写死 `LIMIT 2`；`price_history` 只有 9 个品项、数据停在 10-25 | 不是图表配色或宽度问题 |
| 「复制」字样 | `ui-enhance.js` 的 `bindRowOps()` 往每行 `td:first-child .cell` 注入按钮，而首列是 40px 复选框列；`.ui-row-ops` 虽 `opacity:0` 但 `inline-flex` 仍占宽，把单元格内容顶到第二行 | 不是文案没翻译 |
| 质检之后太随便 | 检测项硬编码 6 条、对任何产品同一套值；前端不渲染实测值输入框；结论由人工点两个大按钮；结论与数据无校验关系 | 不是「多加几个必填」能解决 |
| 配送没有地图 | 只有文字起终点，`farmer` / `canteen` 表没有经纬度字段 | 不是缺一个图表组件 |

同时查到三处会绕过业务真实的旧设计：

- 入库「实收数量」**预填下单量** → 等于永远零损耗，实秤被绕过；
- 入库「质检结果」是可自由选择的下拉，但后端根本不读这个字段 → 选了不生效；
- 损耗可以不写原因就确认入库 → 结算单上的扣减数字无法对账。

## 二、逐项改造

### 1. 行情价格：真实成交价 + 分组自选

**口径换掉**：不再读静态 `price_history`，改为从 `orders` 聚合**真实成交均价**（剔除 status 41 驳回 / 99 作废、数量 > 0）。当前覆盖 27 个品项、5-01 ~ 11-10。

- `StatMapper.priceProducts()`：按品项列出可选清单（品类 / 成交量 / 均价 / 最低最高价 / 最近成交日）
- `priceTrendDaily(ids, days)` / `priceTrendWeekly(ids, days)`：按选中品项取时序
  - 默认 90 天：单品 30 天只有 3~5 笔成交，按**周**聚合才有可读趋势；≤30 天按日聚合
  - 最多同时对比 4 条曲线
- 后端返回 `priceOptions / priceSeries / priceSource`，前端是**按一级品类分组的多选 + 时间窗下拉**（7 / 30 / 90 / 半年），首次加载把后端默认值同步回选择器
- `AdminController.dashboard` 接受 `priceProducts` / `priceDays`；`parseIds` 对非法片段忽略而不是 500
- 卡片上标明口径：`真实成交均价（元/kg）· 剔除驳回/作废订单 · 按周聚合`，日期区间显示在图表下方，不跟图例混在一起

### 2. 「复制」字样

- `ui-enhance.js`：删除 `bindRowOps()`、`data-ui-copy-row` 点击分支、以及仅用于重建该按钮的 `MutationObserver`；`rowNo()` 改为优先取 `.mono`，退化时取第一个含字母数字的单元格
- `global.css`：删掉两处 `.ui-row-ops` 规则
- `enhancePage()` 增加路由切换时清理失效表格引用
- 保留的是底部批量浮动条里的「复制所选单号」（在 `.lay-content` 之外），这是用户主动勾选后的功能，不是行内残留

### 3. 质检：分品类标准库 + 后端自动判定

**新建 `db/06_quality_standard.sql`**：`quality_standard(category_id, item_name, method, unit, min_value, max_value, judge_type, required, sample_spec, sort)`，覆盖 6 个一级品类共 38 项。标准按品类有区别，例如：

- 根茎类多「重金属铅 ≤0.1」「机械损伤率 ≤2」
- 菌菇类含水率设**上限 ≤92%** 而不是下限，用于识别泡水增重；杂质率 ≤0.5%
- 有机菜农残收紧到 ≤0.01，并增加「有机证书核验」

商品档案挂二级品类（白萝卜 / 香菇），标准挂一级品类（根茎类 / 菌菇类），`QualityService.topCategoryId()` 做父级回溯；没配标准时退回叶菜类并在页面标注 `standardFallback`。

**录入与判定**：

- 检测项改成 4 列表格：检测项 / 方法与限值 / 实测值 / 判定
- 前端与后端**同一套 `judge()` 规则**实时预演，超限项整行变红并显示「高于上限 0.05」
- 「未检出 / ND / n.d. / `<` `＜` `≤` 开头」按**低于检出限 → 合格**处理（检测报告的标准写法，不能当异常）
- 结论区从两个可点的大按钮改成只读判定框；标题行另有实时徽标（`待录入 N 项` / `不合格 · N 项超限` / `全部达标`），录数据时不用滚动就能看到整体结论
- **后端二次判定**：前端传的 `result` 只用于比对，`submit()` 按限值重算 `autoResult`，不一致直接拒绝；缺必检项拒绝；不合格要求备注 ≥10 字且至少一张照片
- 照片走真实上传 `/files/upload?type=quality`；抽检数量可编辑但不超过订单量

### 4. 配送 / 入库：把「点一下就过」改成有据可依

**坐标与流水**（新建 `db/07_geo.sql`、`db/08_delivery_temp.sql`）：

- `farmer.lng/lat`、`canteen.lng/lat` 以第一食堂为锚点，按各农户 `distance_km` 与黄金角方位角反推，保证**地图上量出来的距离与里程字段一致**（15km 的丰禾农业验证为直角边合 15.0km）
- `delivery_temp_log`：温度不再是「一个会被覆盖的字段」，发车与每次上报都留流水，能证明一路上有没有断链

**发车检查**：车辆、司机、批次号必填，订单必须 status=40（质检通过），车厢温度必须在 2~8℃，超范围直接禁用提交。

**扫码交付**：必须录入批次号后 6 位，与 `tail(batch,6)` 大写比对，不符给出掩码提示（`应为 04****`）。行内快捷按钮也走同一弹窗，不能绕过。

**入库实秤**：实收数量**不再预填**，质检结果改只读（只认质检报告），有损耗必须写 ≥5 字原因（后端 `InboundService` 也拦一道，原因会写进结算单），达阈值时二次确认。

### 5. 动态实时地图

`frontend/src/components/DeliveryMap.vue`：**自绘 SVG，不依赖外网瓦片**（内网 / 离线可用）。

- 坐标来自后端真实字段，用 `cos(midLat)` 做等比投影，路线不压扁
- 已完成路段实线、剩余路段虚线；车辆三角沿路径旋转，位置取**路径上的进度点**，保证车在路上
- 5 秒轮询 `/deliveries/{id}/track`，HUD 显示状态 / 已行驶 / 剩余 / 预计到达 / 车厢温度；温度 chip 来自流水表
- 进度跑满但未扫码交付时，状态改为「已抵达 · 待扫码交付」，不再显示「运输中 · 0 分钟」
- 起终点标签抬到车辆光晕之外，发车时车不压起点地名、抵达时不压终点地名
- `hasGeo=false` 时明确显示「缺少坐标，无法绘制轨迹」，**不画假地图**
- 卡片底部声明：路线为里程示意，位置按发车时间与平均车速推算，实际以导航为准

## 三、复查截图时又发现并修掉的 6 个缺陷

逐张看图而不是只读脚本输出，才发现这些：

| 缺陷 | 根因 | 修法 |
| --- | --- | --- |
| 「规格 0 kg/批」「样本规格 0 kg/批」 | `fmtNum(v, digits=0)` 默认 0 位小数，`0.30` 被四舍五入成 `0`、`0.50` 成 `1` | 新增 `fmtQty()`（整数不补位、带小数留 2 位），用于样本规格、订单量、实收量、损耗量 |
| 损耗 0.5kg 显示成「0kg」 | 同上，`OrderDetailDrawer.vue` 也用了 `fmtNum` | 同上改 `fmtQty`，结算单与详情页不再丢精度 |
| 录数据时看不到整体结论 | 结论区在表格下方，需滚动 | 标题行加实时判定徽标 |
| 车压住起点地名 | 标签 `y=-16`，而车辆光晕半径 26 | 起终点标签统一抬到 `-34`，上方空间不足时翻到下方 |
| 图例被裁成「红苕」、图例与日期挤成一行 | 日期范围放在卡片 header 的 extra 槽；`.card-extra` 缺 `min-width:0`，flex 项目拒绝收缩 | 日期移到图表下方口径行并与说明分隔；`.card-extra` 加 `min-width:0`，图例 `justify-content:flex-end` |
| night 模式结算金额白字压亮青绿底，对比度 < 3:1 | `global.css` 有一条 `!important` 把 `.eg-amount` 写死 `#FFFFFF`，注释还是「绿色金额条保留白字」——那是 accent 尚为深绿时的老假设 | 改用已有的 `--accent-ink` token（day/paper 白、night 深 `#06231F`） |

另外把三条**过时的验收断言**对齐到现在的设计：`ui_unify_acceptance.cjs` 还在检查已按 L-020 移除的 DOM 层即时筛选、行内复制按钮，以及早已搬进用户菜单的 `.lay-scheme-btn`。现在改成断言「不出现这些假交互 + 服务端筛选条仍在 + 行内无复制按钮」，把本轮修复变成常驻回归。

## 五、还没解决的边界（如实说明）

1. **地图不是真实 GPS**。位置由「发车时间 × 平均车速 32km/h × 里程」推算，路线是二次贝塞尔曲线示意，不是路网导航。要做真地图需要接入车载定位设备或地图服务，并新增坐标上报接口。
2. **温度流水仍依赖人工上报**。目前发车时录一次、运输中可手工更新；没有 IoT 传感器自动采集，所以「断链证明」的完整性取决于上报纪律。
3. **质检标准是演示用的品类限值**，不是经过认证的完整国标文件；`quality_standard` 表已建好，正式使用前应由食安人员按实际执行的 GB 2763 / GB 2762 等标准逐项核对。
4. **扫码交付是「批次尾号核对」**，不是真正的扫码枪 / 二维码解析；批次二维码仍是生成后展示，未接入扫码设备。
5. **反复跑闭环会消耗演示库存**（本轮多次运行后马铃薯库存为 0），这也让「低于覆盖线 → 采购建议」有了可演示场景；需要恢复基线时从数据库备份还原。
6. **照片存在本地文件服务**，未接对象存储与防篡改留痕。

这些不是「还没做完的功能」，而是**需要外部设备 / 真实数据源才能做实**的部分；当前实现已经把「能被绕过的地方」全部堵上，界面里也明确标注了推算口径，不把示意当真实数据展示。
