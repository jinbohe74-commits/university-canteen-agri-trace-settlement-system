## 四、P2 / P3 已修项

- **异常处理**：`GlobalExceptionHandler` 补齐 `MethodArgumentNotValidException / BindException / ConstraintViolationException / MissingServletRequestParameterException / MethodArgumentTypeMismatchException / HttpMessageNotReadableException / MaxUploadSizeExceededException / DuplicateKeyException / NoHandlerFoundException`；兜底异常只写日志，返回固定文案 `系统繁忙，请稍后重试`，不再回显 Jackson 堆栈/SQL。
- **DTO 校验**：`InboundDTO`、`QualitySubmitDTO`、`EvaluationDTO` 补 Bean Validation，对应 Controller 加 `@Valid`；空质检请求从 404/500 变为 **code 400**。

- **日期契约**：新增 `JacksonConfig`，`LocalDateTime` 同时接受 ISO 与 `yyyy-MM-dd HH:mm:ss`，非法格式返回 400 固定文案。
- **CORS / 逻辑删除 / HTTP 状态**：CORS 改显式来源白名单；移除与 25 张表脱节的 `logic-delete-field` 配置；未登录返回真实 HTTP 401（原先 HTTP 200 + 业务码 401）。
- **运维**：`start.bat` 显式 `--server.port=8080`、移除明文口令、保持 GBK 与 `chcp 936` 一致；`.gitignore` 补 `target/`、`config/jwt.secret`、`token-revocations.txt`、`uploads/`、备份目录。

## 五、修复过程中新发现并修复的 3 个兼容性问题

严格角色鉴权上线后，前端巡检从「29/30 + 1 缺陷复现」变成「4 个页面 403/401」，说明修复本身暴露了原先被无鉴权掩盖的设计问题：

1. **多角色共用组件调用管理员接口（403）**：`admin/trace`、`trace`、`purchaser/trace`、`inspector/trace` 四个路由复用同一个 `views/admin/Trace.vue`，组件硬编码 `adminApi.trace()` → `/api/admin/trace`。修复：扩展 `CommonController.trace` 返回 `recent + 可选 trace`（结构与 `/api/admin/trace` 一致，旧调用方兼容），前端统一改用 `commonApi.trace`。**未为修图重新开放任何免鉴权路径**。
2. **二维码 `<img src>` 无法带 token（401）**：`TraceVO.qrCode` 原为 `/api/files/qrcode/x.png`，浏览器直连受控文件接口被拒。修复：`TraceService.getTrace()` 读取 qrDir 下真实文件，内联为 `data:image/png;base64,...` 返回，存量数据与二维码生成逻辑不变，前端零改动。
3. **登录页弱口令残留**：首轮只改了展示文案，`form.password:'123456'` 预填与 `pickRole` 自动填充仍在，被新增的静态检查断言抓到。修复：清空初始值、移除 `account` 字段与自动填充、角色按钮只做视觉提示。

## 八、环境与复跑

```bash
# 1) 后端（必须显式指定端口，否则被环境注入 62531 且端口冲突）
cd backend
mvn -B -q clean package -DskipTests      # 打包前先停掉正在运行的 jar
java -Dfile.encoding=UTF-8 -jar target/canteen-trace.jar --server.port=8080

# 2) 前端
cd frontend && npm run dev -- --host 127.0.0.1 --port 5173

# 3) 三层回归
cd backend && mvn -B -q test
cd .. && PYTHONIOENCODING=utf-8 python tools/review_system_test.py
node tools/review_pw_check.cjs
```

- 本机会话有 `HTTP_PROXY`，本地请求必须绕过（curl `--noproxy '*'` / Python `ProxyHandler({})`）。
- Playwright 浏览器缓存版本不匹配，巡检脚本复用系统 Edge：`chromium.launch({ channel: 'msedge' })`。
- **生产部署前必须注入 `CANTEEN_JWT_SECRET`**：未注入时虽会生成随机密钥文件，但该密钥落在本地磁盘且多实例部署不共享，跨实例 token 会失效。
- `config/jwt.secret`、`config/token-revocations.txt`、`uploads/` 已加入 `.gitignore`；`token-revocations.txt` 会随注销记录累积，长期运行建议迁移到 Redis 并设置 TTL。

## 十、结论

P0 五项与 P1 十四项已全部修复并通过动态回归验证；认证授权层从「可被任意角色绕过」收敛为「服务端按 URL 前缀强制鉴权 + 数据库角色为准 + 可吊销 token」，文件接口不再有免鉴权入口，前端权限不再依赖可篡改的 localStorage。三层测试资产已从缺陷特征化翻转为回归门禁，**全量 `mvn test` 66 用例 0 失败、系统回归 69 项 0 FAIL、前端 30/30 页面 + 3 项安全断言全通过**，演示数据零污染。
