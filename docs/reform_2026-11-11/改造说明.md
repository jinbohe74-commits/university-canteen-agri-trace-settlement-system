# 第五轮整改说明（2026-11-11）

> 反馈原文：
> 「很多方框只能看，点击没反应，华而不实，点击方框应该要显示相应的详细信息或出现对应的功能；顶部栏动态这个功能很鸡肋，应该将信息发送给相应有关的人，而不是所有人都接收到；有些导出的 excel 表格杂乱不堪，特别是数据看板里面的导出报表，全部挤在一个标签页里面；最后，配送中，已入库，待结算，和已结算这几个过程一点使用体验都没有，好像就是一个形式。」

## 一、取证结论（先查数据，再动手）

| 反馈 | 证据 | 根因 |
|---|---|---|
| 方框点了没反应 | 全项目 63 个 `StatCard` 实例，只有 1 个传了 `clickable @click`；数据看板主指标带还是自绘 `.db-primary/.db-mini`，根本没走组件 | 卡片是「可选装饰点击」，没有统一的「指标 → 明细」契约 |
| 动态谁都收得到 | `sys_event` 三条 SQL 无 `user_id` 过滤；AOP `peersOf(role)` 把每次写操作广播给除本人外全部角色；129 条事件里 125 条没有具体接收人，正文是「姓名+固定动作+接口路径」 | 拿全量事件流当消息中心，没有业务归属解析 |
| 导出报表全挤一个标签页 | `exportSectionsCsv()` 把 8 段不同列数的报表用 `# 标题 + 空行` 顺序拼进一个 `.csv` | CSV 格式本身没有工作表概念 |
| 四个状态像做样子 | `已入库(70)`、`已结算(90)` 在前端 0 个状态码条件分支；订单抽屉全是只读 `el-descriptions` | 只有状态展示模型（StatusTag / 步骤条 / tab），没有「状态 → 可执行动作」契约 |

按经验库 L-043（「华而不实」同类问题）处理：不在每个页面逐个补按钮，而是补四套**机制层契约**。

## 二、四项机制改造

### 1. KPI 卡片统一钻取

- `frontend/src/utils/statDrill.js`：全局 `statDrillState` + `DRILL` 注册表（60+ 指标 → 真实接口 → 数据来源 → 跳转路由），`openStatDrill()` 未登记的指标也保证有反馈（不会点了没反应）。
- `frontend/src/components/StatDetailDrawer.vue`：显示当前值、口径说明、数据来源、真实明细表（最多 50 条）、「查看完整列表」。
- `frontend/src/components/StatCard.vue`：**默认所有卡片可点**，显示「明细 ›」；父级显式绑了 `@click` 的（ Farmers「待审核」）保留原行为。判断父级点击用 `getCurrentInstance().vnode.props.onClick`——`defineEmits(['click'])` 会让 `useAttrs().onClick` 恒为空。
- `frontend/src/layout/AppLayout.vue`：全局挂载抽屉，所有页面自动生效。
- `frontend/src/views/admin/Dashboard.vue`：自绘的 4 个主指标方框也接入同一契约；新增 `GET /api/admin/quality-reports` 给「质检合格率」提供真实逐批质检记录。
- 顺带修假数据：`FarmerService.sourceStats()` 里「本月成交」原为 `all.size() * 8`，改为 `OrdersMapper.countMonthDeals(farmerId)` 真实统计。

### 2. 动态 → 定向通知

- `db/10_notification.sql`：新建 `sys_notification`（`recipient_id` + 索引 + 幂等去重清理）。
- 后端 `SysNotification` / `SysNotificationMapper` / `NotificationService` / `NotificationController`：
  - SQL 层就带 `recipient_id = 当前用户`，前端拿不到别人的消息；标已读也带该条件。
  - 接收人解析优先级：**订单所属农户 / 收货食堂绑定账号 > 该订单实际质检员 > 角色兜底**；不再把 `role_type='PURCHASER'` 全部账号群发。
  - 一次事件内用 `Set<Long> sent` 去重，避免同一账号被 `CANTEEN` 与 `PURCHASER` 双重解析出两条。
  - 不给操作者自己发；通知是旁路，异常吞掉不影响主业务。
- 六个业务节点显式发布：发货(SHIP)、质检(QUALITY)、发车(DEPART)、交付(ARRIVE)、入库(INBOUND)、结算审核(SETTLE)，每条带业务单号、真实数字、发送人、点击路由。
- 前端 `notificationApi` / `utils/notification.js` / 顶栏「通知」面板 / 看板「与我相关的通知」卡片：15 秒轮询 + 打开面板即刷新 + 点击标已读并跳业务页。
- **SSE 与用户消息分离**（关键）：`RealtimeAspect` 不再产生「给用户看的动态」，改为静默 `CACHE_INVALIDATE` 技术信号，只触发 `canteen:data-changed` 让在线页面自动刷新；前端不进通知中心、不产生未读数。这样既保留了跨角色自动刷新，又不会让所有人看到与自己无关的消息。

### 3. 导出 → 多工作表 xlsx

- 新增 `xlsx@0.18.5` 与 `frontend/src/utils/exportWorkbook.js`：每段 `aoa_to_sheet` + `book_append_sheet`，工作表名处理 Excel 限制（≤31 字符、非法字符、重名），按内容估算列宽、冻结表头行。
- `utils/export.js` 保留 `exportSectionsCsv()` 旧函数名兼容，内部改调 `exportWorkbook()`；`Dashboard.exportReport()` 输出 8 个工作表：`核心指标 / 近 6 个月订单量 / 采购品类分布 / 价格行情 / 待办事项 / 本月结算 / 农户信用 Top5 / 各食堂采购占比`。
- 阶段动作里的配送记录、验收单、结算凭证也统一改成真实 `.xlsx`（结算凭证含「结算单 + 扣款依据」两个工作表）。

### 4. 四状态 → 可执行动作

- `frontend/src/components/OrderStageActions.vue`：`STAGE` 表把状态码映射为「当前阶段 / 下一步 / 动作集」，按角色裁剪。
  - `50 配送中`：查看实时轨迹、配送单详情、导出配送记录、去扫码交付
  - `70 已入库`：查看验收单、导出验收单、查看在库库存、去结算审核
  - `80 待结算`：查看结算单、导出结算明细、去审核结算、查看我的对账单
  - `90 已结算`：查看结算明细、下载结算凭证、去评价本次供货、查看我的对账单
- `frontend/src/components/OrderDetailDrawer.vue`：步骤条下方插入动作区，所有角色的订单详情都生效。
- `DeliveryService.trackByOrder()` + `GET /api/common/orders/{orderId}/track`：四角色共用轨迹，仍由 `orderService.checkDataScope(o)` 校验数据权限；无配送单时也先做权限校验，避免用它探测他人订单。
- 轨迹弹窗复用 `DeliveryMap.vue` + 温度流水 + 5 秒轮询。

## 三、过程中发现并修掉的次生缺陷

1. `notifState` 导出的是响应式对象，`AppLayout`/`Dashboard` 却写 `notifState()` → 统一改成 `export function notifState(){return state}`（与 `realtimeState()` 一致）。
2. `SELECT DISTINCT inspector_id ... ORDER BY id DESC` 触发 MySQL 8 错误 3065，被通知旁路的 try-catch 吞掉 → SHIP 通知整批静默丢失。改 `GROUP BY inspector_id ORDER BY MAX(id) DESC`，并补端到端通知断言。
3. 关掉 AOP 广播后 `usability_verify` 的「采购员自动拉到新货源」回归失败（autoCalls=0）→ 恢复 AOP，但只发静默缓存失效信号。
4. 同一账号收到重复通知、无关账号（purchaser02/03/04、inspector02）也收到消息 → 按订单归属解析 + 事件内去重 + `db/10_notification.sql` 幂等清理历史重复行。
5. `InboundService` 新增 `NotificationService` 依赖后 11 个单测空指针 → 补 mock，并新增「入库只通知农户+审核管理员、不广播」契约用例。
6. `filters_check.cjs` 用 `.stat-card.stat-click:first` 定位「待审核」，在「所有卡片都可点」后指错对象 → 改成按语义 `hasText:'待审核'` 定位。
7. 看板自绘主指标方框原本不在钻取覆盖范围 → 一并接入。

## 五、遗留边界（如实说明）

- 地图是**里程示意**：起终点经纬度来自 `farmer.lng/lat`、`canteen.lng/lat`，路线为二次贝塞尔示意，位置按发车时间与平均车速推算；不是真实 GPS / 路网导航。
- 冷链温度依赖发车登记 + 途中人工上报，未接物联网探头。
- 质检限值是演示标准库，不是法定检测限值；扫码交付是「批次号后 6 位核对」，不是真扫码枪对接。
- 结算审核管理员目前仍是「角色队列」通知（系统无按单指派审核人的字段），这是唯一保留的角色级接收，但仅限管理员审核队列，不会广播给农户/采购/质检。
- SSE 的 `CACHE_INVALIDATE` 对所有在线连接可见，这是**技术刷新信号**，不产生任何用户可见消息、未读数或动态条目。
- `sys_notification` 历史数据已按幂等脚本去重；本轮测试产生的订单、通知为真实业务链路数据，未做删库。
