# 第十轮改造：配送任务工作台重排 + 采购需求列表与待办深链

> 用户反馈：
> 1. 「质检员的配送任务功能模块不好用，感觉用起来很别扭」
> 2. 「农户采购需求的需求列表设计得很不合理，让人感觉很杂乱，从待办里面点去比价，又是只是跳转界面，很难找到要比价的需求编号」

两条都不是"少个按钮"。第一条是**默认选错了对象**，第二条一半是**脏数据**、一半是**跳转不带定位**。

## 一、配送任务为什么"别扭"

### 取证（截图里那一屏）

| 现象 | 代码位置 | 结论 |
|---|---|---|
| 一进来，「当前配送任务」是 **10-04 已交付** 的单（PS20261004360） | `DeliveryService.tasks()`：`current = 第一条`，列表按 `createTime ASC` | 没有在途单时，**最老的历史单**被当成了当前工作 |
| 它的「运输节点」显示 **0/4 全灰** | `traces` JSON 里早期种子数据没有 `done` 字段 | 节点状态依赖落库快照，历史数据不规范就显示错 |
| 待发车的单显示 **2/4**（装货、运输中已完成） | `buildTraces()` 前两个节点恒 `done=true` | 没发车就"已装货已运输"，凭空多两个节点 |
| 「实时轨迹」还在给这张历史单画线、5 秒刷新 | 定时器无条件 `setInterval` | 已交付的单轮询没有意义 |
| 下方「今日配送任务」里 **14 条已交付** + 1 条待办平铺 | 表格直接用 `records` | 干活要在一堆历史单里找那一条 |
| 右上角「+ 配送单」点了只弹"自动生成" | `createTip()` | 假按钮 |

### 改法

| 位置 | 改前 | 改后 |
|---|---|---|
| 默认选中 | 有在途用它，否则列表第一条 | 只在 **待发车 / 在途** 里挑；都没有就 `current = null` |
| 无待办时 | 拿历史单顶替 | 明确空态：「当前没有待发车或在途的配送任务，最近一单 X 已于 … 交付」+「查看已交付的 14 单」 |
| 顶部 | 无 | **作业状态条**：待发车 / 在途 / 已交付待入库 / 全部，带真实数字，点数字切页签 |
| 任务表 | 全部平铺，标题「今日配送任务」 | 按页签分流，默认只列待处理；点已交付行时标题变「历史配送单」并出提示条 |
| 运输节点 done | 读落库快照 | `view()` 里按状态现算：`done = arrived \|\| (started && i < 2)`；未发生的节点时间标「预计」 |
| 实时轨迹 | 永远 5 秒轮询 | 仅「配送中」轮询；已交付标「轨迹定格」；待发车用紧凑占位条 +「去发车检查」 |
| 假按钮 | 「+ 配送单」 | 删除 |
| 本批装载 | 已交付单也挂同车其他批次 | 历史单只显示它自己那一批 |

## 二、需求列表为什么"杂乱"

### 取证

```sql
SELECT status, COUNT(*) FROM purchase_demand GROUP BY status;
-- 处理中 9 / 已完成 5 / 已成交 25 / 已撤回 5   （清理前 48 条）
```

按品项分组后，`11-10~11-11` 之间出现了 **成对的同款需求**：

| 数量 | 单价 | 出现次数 |
|---|---|---|
| 马铃薯 43 kg | ¥2.18 | 8 次 |
| 白萝卜 600 kg | ¥2.30 | 8 次 |

这两条是历次验收/演示脚本反复发布留下的（`X20261111139~147`、`X20261110132~137`）。**"杂乱"的第一因是数据，不是样式**——首屏全是数量、单价、品类完全一样的历史单，谁看都觉得是假数据。

### 数据清理

只删**能安全删**的：

```sql
-- 备份
CREATE TABLE purchase_demand_bak_20261111 LIKE purchase_demand;
INSERT IGNORE INTO purchase_demand_bak_20261111 SELECT * FROM purchase_demand;

-- 同一 (食堂,品项,数量,单价) 的「处理中」重复单：0 报价、无订单引用、保留最新一条
DELETE d FROM purchase_demand d JOIN ( … GROUP BY 保留 max(id) … ) x ON x.id = d.id;
```

清了 4 条（`X20261110137/1139/1141/1143`），备份表 48 行。**已成交的重复单没动**：它们挂着真实测试订单，删了就断订单链（L-058 的判断标准）。

### 界面重排

| 位置 | 改前 | 改后 |
|---|---|---|
| 默认页签 | 全部（20+ 条历史单） | **待比价**（6 条，真正要动手的） |
| 列 | 编号 / 产品 / 品类 / 数量 / 期望价 / 期望交货(96px 被截断) / 状态 / 报价数 / 操作（3 个链接挤一格） | 编号+创建时间 / 品项+品类 / 数量 / 期望单价 / **交货截止 + 剩 N 天** / 报价数或红标「等报价」/ 状态 / **一个主操作** |
| 发布表单 | 常驻右侧 1fr，和列表抢版面 | 收进抽屉，页头一个「发布需求」 |
| 定标后 | 强制跳到「我的订单」 | 留在需求页继续比下一条（消息里说明去哪看订单） |
| 统计卡 | 匹配中 | 待比价（foot："需要你定标"） |

## 三、待办「去比价」只跳转，找不到编号

### 根因

`TodoCenterService` 的需求待办只给了 `path = "/purchaser/demands"`，落地页拿不到"要找哪一条"，用户只能自己在列表里比对编号。这和上一轮扫码交付抄错批次是同一种病：**入口给的定位信息，和目标页认的定位信息不是一回事**。

### 改法

- 后端待办条目补 `demandId` / `demandNo`，`path = /purchaser/demands?focus=<需求编号>`；质检待办 `path = /inspector/delivery?focus=<订单号>`、`/inspector/quality?orderId=<id>`。
- 需求页读 `route.query.focus`：**自动切到「全部」并按编号筛选 → 该行高亮 → 直接打开比价面板**，顶部显示「正在定位待办需求 X20261110133，已打开比价面板」+「查看全部需求」。
- 配送页读 `route.query.focus`：按订单号/配送单号定位到上方作业区。
