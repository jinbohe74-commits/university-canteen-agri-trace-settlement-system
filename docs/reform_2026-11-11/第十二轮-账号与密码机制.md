# 第十二轮：账号与密码机制

> 用户原话：**"现在的问题是创建各个角色的账户和密码的机制不完善"**
>
> 本轮不做界面美化，只把「一个账号从创建到能干活、到能改自己的密码」这条链路补完整。

---

## 一、先取证：不完善的到底是哪一段

没有直接改代码，而是先用真实请求把"新建一个农户账号"完整走了一遍：

| 观察 | 实测结果 | 说明 |
|---|---|---|
| 只传 `roleType`、不传 `roleId` 建号 | 建号成功，但 `menus: []` | 登录后侧边栏空白，页面进去是空的 |
| 新建农户账号后登录 | `farmerId: null`，`/api/farmer/workbench` 返回 **403「当前账号未绑定农户档案」** | 账号"能登录"，但什么业务都干不了 |
| 建号接口响应体 | 直接返回 `password: "$2a$10$..."` | BCrypt 哈希被序列化给了前端 |
| 自助改密 | 全站没有这个入口 | 用户想改密码只能找管理员重置 |
| 采购员未绑定食堂 | `purchaserHome()` 用 `eq(canteenId != null, ...)`，为 null 时**退化成查全量** | 一个没有归属的账号能看到所有食堂的数据 |

根因只有一句话：**账号被当成孤立的一条 `sys_user` 记录，而不是「账号 + 角色 + 业务档案」三件套。**
角色关系交给前端传 `roleId`，业务档案压根没管，密码只由管理员单向发放、没有回收路径。

---

## 二、改了什么

### 1. 建号契约：三件套必须在同一次保存里落全

后端 `UserService.save(...)` 重写：

- **角色以 `roleType` 为准反查 `sys_role`**。前端传的 `roleId` 只做一致性校验，不再直接落库。
  这样即使前端角色列表没加载出来，也不会再建出"没有 `sys_user_role` 记录"的账号。
- **农户必须绑农户档案、采购员必须绑食堂**，不绑直接 400，并说明"否则登录后看不到自己的订单"；
  管理员/质检员是平台岗位，不要求绑定，并且会把旧绑定清掉。
- **档案与账号一对一**：目标档案已被别的账号占用时返回 409 并点名占用者，不做静默抢占。
- **换绑/换角色自动解绑**：农户改成质检员，`farmer.user_id` 自动置空，档案回到可绑定池。
- **账号格式**：`^[A-Za-z][A-Za-z0-9_]{2,23}$`，拒绝中文、空格和纯数字，避免"看着一样、登不进去"。
- 建号/改密后 `need_change_pwd = 1`，编辑时若传了密码同样要求下次登录改。
- 响应体改为脱敏 Map；`SysUser.password` 加 `@JsonIgnore`，**任何接口都不会再吐出哈希**。

新增接口：

| 接口 | 用途 |
|---|---|
| `GET /api/admin/users/bindable?roleType=&userId=` | 建号/改绑时可选档案，只返回未被其他账号占用的 |
| `GET /api/admin/users/password-suggestion` | 生成一个必定合规的 10 位随机初始密码 |

### 2. 密码机制：从"一次性口令"变成"必须改、能自己改"

- 新增字段 `sys_user.need_change_pwd`、`pwd_update_time`（`db/12_account_mechanism.sql`）。
- 新增 `PUT /api/auth/password`：校验当前密码 → 校验强度 → 改密 → **吊销该用户其他所有 token**
  → 用 `cutoff + 1` 重新签发当前会话 token（本人不用重新登录，别处已登录的会话立即掉线）。
- `AuthInterceptor` 对未改密账号只放行 `/api/auth/{me,password,logout}`，其余返回 **428**。
- 密码策略收敛为唯一一份 `PasswordPolicy`：≥8 位、字母+数字、长度上限 24、拒绝 `admin123` 这类常见弱口令。
  建号、重置、自助改密三处共用，不再各写一套。
- 停用账号时 `online` 一并清零；**禁止停用当前登录的自己**；**禁止停用最后一个启用的管理员**。

### 3. 界面：建号即交付，交付即可用

用户与权限页：

- 新增「所属单位」列（档案名 + 档案编号）；平台岗位显示"平台账号 · 不绑定档案"，不再误报"未绑定档案"。
- 状态列合并展示启用状态、`待改密` / `已锁定` 标记与最近登录时间。
- 新增用户弹窗：
  - 选「农户」/「采购员」时**自动出现绑定档案下拉**，并说明该角色的数据范围；
  - 初始密码支持「随机生成」「复制」，提示"首次登录会被要求修改"；
  - 创建成功后弹出**账号凭证卡片**（账号/姓名/角色/所属/初始密码），一键复制全部转交。
- 重置密码同样弹凭证卡片，不再是几秒就消失的 toast。
- 顶栏用户菜单新增「修改密码」；首次登录时弹出**不可关闭**的强制改密框；
  未改密前主内容区显示占位说明，不挂载业务页（避免每页都打一批注定 428 的请求）。

## 三、验收

### 接口层 `tools/account_mechanism_acceptance.cjs` — **41/41 通过**

覆盖四组：

- **A 建号契约**：不绑档案/中文账号/含空格/弱口令/档案已被占用 → 全部明确拒绝；
  被拒后不留下半成品账号。
- **B 建号有效性**：故意不传 `roleId` 建号 → 菜单非空；绑定档案 → 登录即返回 `orgName` 与 `farmerId`；
  未改密访问业务接口 → 428。
- **C 密码机制**：旧密码错/新旧相同 → 拒绝；改密成功 → 旧 token 401、新 token 直接可用、
  旧密码不能再登录、新密码可登录、工作台恢复。
- **D 权限收口**：档案不能重复绑定；改角色自动解绑并回到可绑定池；停用即下线；
  不能停用自己；平台岗位无需绑定；重置后的口令可登录并再次要求改密。

## 四、已知边界（明确不做/留待后续）

1. **历史演示账号不强制改密**：迁移脚本把存量账号的 `need_change_pwd` 置 0，否则演示环境一登录就被弹窗拦住。
   管理员主动"重置密码"后仍会强制改密，这是刻意保留的唯一入口。
2. **账号不能删除，只能停用**：删号会牵扯订单/日志外键，本轮不引入软删除。
3. **token 吊销仍是单机文件**：多实例部署需要换成 Redis 或数据库共享存储，接口已留好。
4. **一个档案只能绑一个账号**：真实场景若存在"一个合作社多个经办人"，需要把一对一放宽为一对多，
   届时 `farmer.user_id` 要改成关联表。
