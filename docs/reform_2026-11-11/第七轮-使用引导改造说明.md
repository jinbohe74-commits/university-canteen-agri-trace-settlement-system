# 第七轮：从「用不明白」到「进来就知道该干什么」

> 用户原话：**「你模仿现实中的几个角色去使用一番，我有点使用不明白」**
>
> 交付物：`docs/reform_2026-11-11/使用手册-四角色怎么用.html`（带真实截图的操作手册）

## 一、先当用户走一遍：问题不在单页，在"页与页之间"

以四个账号真实登录，逐页记录 31 个页面（`tools/role_walkthrough.cjs`，基线数据在 `walk_before/`）：

| 指标 | 结果 |
|---|---|
| 页面有副标题说明"这页干什么" | 30 / 31（仅质检员「我的任务」用 hero 横幅代替） |
| 首屏有主操作按钮 | 22 / 31 |
| **页面上出现"下一步 / 上游 / 完成后"这类流程提示** | **0 / 31** |
| 控制台报错 / 空白页 | 0 |

结论很清楚：**每一页都能自证，但没有一页告诉用户"我在整条链的第几步、做完谁接手、今天先干哪件"**。四个角色各自看到 5~11 个功能菜单，却没有一张"我的工作主线"，所以只能一页页试——这就是"用不明白"的结构性原因，不是某个按钮难看。

## 二、机制层改造（一处建设，四角色同时生效）

### 1. `GET /api/common/my-flow` —— 角色主线（`FlowService.java`）

按当前角色返回：

- `duty`：一句话岗位职责；
- `pipeline`：全链路四棒（农户供货 → 采购下单 → 质检配送 → 入库结算），标出"你在这"；
- `steps`：**5 步工作主线**，每步含 `what`（业务语言要做什么）、`count`（**库里真实待办数**）、`next`（做完谁接手）、`path` + `cta`（一键直达）、`urgent`（是否卡住下一棒）；
- `tips`：角色相关的真实规则答疑（权限、数据隔离、通知投递）。

硬约束：数字必须能被对应业务接口复算。实测：

| 角色 | 步骤 | 引导显示 | 业务接口复算 |
|---|---|---|---|
| 管理员 | 审核结算单 | 11 笔待审核 | `settlements?status=待审核` = 11 |
| 管理员 | 处置食安预警 | 13 条待处理 | `warnings?status=待处理` = 13 |
| 采购员 | 实秤验收入库 | 6 笔待验收 | `orders?status=60` = 6 |
| 质检员 | 领质检任务 | 2 批待质检 | `tasks?status=30` = 2 |
| 农户 | 去需求大厅报价 | 7 条待报价 | 处理中需求里本户未报价的 = 7 |

`urgent` 刻意**不按"有数字就红"**：只标真正阻塞下游的环节（结算审核、预警处置、农户接单/发货、采购验收、质检三连）。否则一屏 5 步全红＝没有优先级。

### 2. 「怎么用」面板 + 顶栏流程定位（`GuideDrawer.vue` / `guide.js`）

- 顶栏常驻 **怎么用** 按钮（图标 + 文字）；
- 面包屑后常驻 **`流程 2/5`** 小标，显示当前页面在主线的位置与待办数，点开即面板；
- **首次登录自动打开一次**（按角色记，`ct_guide_seen_<ROLE>`）；判定加"真会话"标记 `sessionStorage.ct_guide_fresh`，只有从登录页登录进来才自动弹，带 token 直进的调试/验收不会被蒙层挡住（这一条是被三套既有脚本的 `overlay intercepts pointer events` 超时逼出来的，已记 L-059）。

### 3. 引导里的每一跳都必须落到"有东西可做"的页面

- 农户「去接单 / 去发货」带 `?status=10 / 20`，直接落到订单页对应标签（`farmer/Orders.vue` 支持 `route.query.status`）；
- **待办为 0 的步骤，跳转时去掉状态筛选**：否则用户点进去是空表，会判定"系统坏了"；同时按钮文案从「去接单」改成「查看」。

## 三、四个角色现在看到什么

| 角色 | 五步主线（括号内为真实计数逻辑） |
|---|---|
| 管理员 | 审核结算单（待审核结算）· 处置食安预警（待处理预警）· 跟进在途订单（30/40/50/60）· 审核农户准入（待审核农户）· 看经营态势（今日新单/采购额） |
| 农户 | 挂货源（在售货源）· 需求大厅报价（未报价的处理中需求）· 确认接单（状态 10）· 备货发货（状态 20，另提示"待质检不用你操作"）· 查结算（待审核结算） |
| 采购员 | 提需求（处理中需求）· 选货源/智能匹配（在售货源 49）· 跟单到货（10~50 在途）· 实秤验收入库（状态 60）· 评价（已结算未评价） |
| 质检员 | 领质检任务（状态 30）· 录入结论（不合格待复检）· 发车配送（状态 40）· 在途跟踪与交付（状态 50）· 异常上报（质检类待处理预警） |

## 四、验收

`tools/guide_acceptance.cjs` —— **60 条断言全绿**：

- 四角色各返回 5 步 + 职责 + 四棒链路，每步都有"做什么/谁接手/入口"，计数都是数字；
- 计数与业务接口复算一致（上表五处）；
- 首次登录自动弹、引导面板无 `undefined/NaN`、顶栏流程标可点开；
- 二次进入不再自动弹；
- 四角色 × 5 步 = 20 次点击，落点全部等于预期 URL（0 待办的步骤自动去掉 `?status=`）；
- 走完五步 0 前端异常。

回归：`mvn test` 75/75；`reform6_acceptance` 41/41；`check_menu` 13/13；`multitab_check` 16/16；`usability_verify` 27/27；`filters_check` 4/4；`reform5_acceptance` 28/28；`vite build` 通过。

> 两处需要如实说明的调整：
> 1. `usability_verify` 的「采购员顶栏通知计数有新增」曾失败——原因是前几轮走查把该账号 16 条通知全点成已读，徽标天然为空。恢复一条未读后 27/27，**接口与推送逻辑未改**。
> 2. 三个走真实 UI 登录的脚本补了一行"若出现引导先关掉"——引导是真实功能，脚本适配产品，不是关掉功能迁就脚本。

## 五、边界（没有假装做到的部分）

- 引导是**导航层**的改进，不会凭空造出业务能力：查不到单据仍明确提示"无法定位"；
- 质检员第 3、4 步共用「配送任务」页（发车 / 在途），流程标显示 `3–4/5`，不假装精确；
- 农户工作台、消息页不在五步主线上，流程标显示「5 步主线 · 点开看我在哪一步」；
- 证照类待办仍只能"标记已处置 + 去预警页"，系统没有证照补传接口。
