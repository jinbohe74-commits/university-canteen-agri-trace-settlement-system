## 二、最重要的一次自我纠错：我的审查方法本身错了

第一轮静态扫描，我用 `grep "route.query"` 判断「页面认不认 ?focus=」，结论是**8 个待办目标页里 5 个完全不认**。

我据此新建了 `utils/focus.js` + `components/FocusBar.vue` + 一套全局样式，改到第三个文件时发现：

```js
// admin/Settlements.vue 第 356 行，早就有了
import { useFocusLocator, makeListFocus } from '@/utils/focusLocator'
```

**7/8 页面已经接了统一实现**，只是它封装在 composable 里，源码里不出现 `route.query` 字样。

真实缺口方向完全相反：**能力齐全，是入口侧没把编号发出去** ——

```java
// 修复前
it.put("path", "/admin/settlements");           // 跳到列表，自己找
// 修复后
it.put("path", "/admin/settlements?focus=" + s.getSettlementNo());
```

已删除新建的 `focus.js` / `FocusBar.vue` / 全局样式，避免两套并存。记入 **L-063**。

## 三、修复清单

### 1. 跨页定位链路补全（管理员 37 件待办里 30 条受影响）

| 环节 | 问题 | 修法 |
|---|---|---|
| 入口（后端） | 结算/预警/农户三类 path 不带编号；订单类 path 全是裸路径 | `orderBase()` 新增 `withFocus()` 统一追加 `?focus=<orderNo>`；三处 path 补编号 |
| 搜索（后端） | `WarningService.keyword` 只搜 target/content，**按预警编号搜不到** | 增加 `warning_no` 匹配 |
| 匹配键（前端） | `FOCUS_KEYS` 没有 `farmerNo` | 补上 |
| 农户审核页 | 完全没接 focus，且 `load()` 有 seq 竞态 —— 两次并发会让先发的结果被丢弃，表现为"筛到了却拿不到行" | 先设 keyword 再串行 load，定位后打开档案 |
| 评价 / 溯源 / 我的任务 / 农户对账 | 4 个页面不认 focus | 全部接入，定位后直接选中/打开详情 |
| 入库页 | 认 `orderNo`，待办传 `focus` | 两个都认 |
| 质检页 | 认 `orderId`，待办传 `focus` | 两个都认 |
| 质检→配送 | 「去发车」只跳页面 | 带上刚质检的订单号，落地直接定位 |

验收：`tools/focus_chain_acceptance.cjs` **13/13**（含"path 必须带 focus"与"落地必须出现定位效果"两类断言）

### 2. 质检录入：实时刷新会把正在填的单切走（L-064）

`boot()` 同时负责"选默认对象"和"取数据"，被 `useAutoRefresh` 复用时重新挑单，表单被换。

修法：已选单只要还在队列就保持不动；同一单不重载详情；只有显式 `?focus=` 或用户主动切单才换。

### 3. 假按钮 → 真功能

| 位置 | 原来 | 现在 |
|---|---|---|
| 质检异常上报「现场照片」 | 三个格子，点了弹"演示环境" | 接**已有**的 `/api/files/upload`：真实上传、缩略图预览、可删除、最多 3 张 |
| 预警详情 | 无照片可看 | 新增 `warning.photo_urls` 字段；详情页显示「现场照片（N 张）」，点击带 token 取图（受控下载，未登录 401） |
| 入库「扫描二维码」 | 弹"演示环境请手动输入" | 聚焦查询框进入扫码待命（扫枪本质是键盘输入），扫完自动回车查询 |
| 智能匹配「调整权重」 | 弹"由管理员配置" | 权重说明弹窗：五项权重条形图 + 公式 + 合计 + 谁维护、为何这样排 |
