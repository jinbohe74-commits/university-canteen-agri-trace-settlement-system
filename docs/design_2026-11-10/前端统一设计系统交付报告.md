# 前端统一设计系统交付报告

**日期**：2026-11-10（第二轮返工）
**触发**：用户反馈「不同方案切换的时候感觉是好几个系统，割裂感太强了」
**结论**：已从生成机制层消除割裂源——把「三套并行设计系统 + 按页面自动轮换」收敛为「**一套设计系统 + 三种明度模式**」，并补齐深色模式全站可读性。

---

## 1. 根因（为什么上一版会割裂）

不是某个色值没对齐，而是上一轮的**实现机制**本身就在制造割裂：

| 层面 | 上一版做法 | 造成的观感 |
|---|---|---|
| 变量层 | A/B/C 各自把字体族、圆角、阴影、导航宽度、密度、纹理全部重定义一遍 | 换主题 = 换字体 + 换几何 + 换明暗 |
| 布局层 | `global.css` 有 60+ 行 `[data-scheme=x]` 分支：C 隐藏侧栏改横向导航、B 藏掉文字只留图标、A 换衬线加大字号改表格密度 | 翻一页导航位置都变了 |
| 主题应用 | `router.meta.scheme` + `router.afterEach` + `main.js` + `AppLayout.resolveScheme` 四处按路径自动分配 | 登录/溯源/驾驶舱各用一套，跨页必然跳变 |
| 内容层 | 登录页整套 A 专属外壳（衬线、直角、纸纹、下划线角色 tab） | 登录页本身就是「另一个系统」 |

> 按经验库 L-006：同类问题第 2 次被提出，必须查生成机制，不能逐件调色。同时如实说明：**L-029 已经记录过「换肤时旧样式硬编码色残留」，但上一轮只修了 Dashboard 的 4 处，没做全站量化审计——属于已知却没做到**；L-027 第 5 条给出的「混搭」写法也缺少「单一底座」约束，等于把方向带偏，本次已修订。

## 2. 这次怎么改

### 2.1 结构常量与颜色语义分层
`tokens.css` 现在只有两层：

- **唯一结构底座**（`:root / html[data-mode]` 全局常量）：一套字体栈、6/10/99px 圆角、一套阴影、208px 左侧栏（图标+文字）、56px 顶栏、密度 1、统一动效与层级。**三档完全一致，不随模式变化**。
- **明度模式** `html[data-mode="day|paper|night"]`：**只覆盖颜色语义变量**，且三档共享同一品牌色相（青绿 h≈166°，实测色相差 1.4°），只做明度适配。
- 保留 `--c-*` 兼容别名 → 28 个业务 view 的 scoped 样式一行不用改即可跟随。

### 2.2 取消按页面自动切换
- 删除 `router.meta.scheme`、`router.afterEach` 主题计算、`AppLayout` 的 `SCHEME_OF / resolveScheme / applyScheme`。
- `main.js` 首屏读 `ct_ui_mode` 设置 `html[data-mode]`；顶栏「外观 · 浅色 / 暖纸 / 深色」全局一次选择、写入 localStorage，**所有页面恒定**。
- 删除 C 的顶部横向导航 DOM，侧栏与命令栏在任何模式、任何页面都存在。
- `BaseChart.vue` 的 MutationObserver 改监听 `data-mode`，切换明度时重绘图表。

### 2.3 内容层与主题解耦
登录页摄影主视觉改为固定的**内容资产**（`brand-hero.png`，三档同一张图、同一遮罩），表单改用全站组件语言（同字体、同圆角、chip 式角色选择）。溯源时间线、驾驶舱图表密度属于页面内容编排，任何模式下都保留，不再绑定主题。

### 2.4 深色模式全站可读性（自动审计驱动）
业务 view 里有大量浅色模式专用的硬编码色，深色下变成「深底深字 / 浅底白块」。规则集中在 `global.css` 的 **night 明度适配层**统一接管，不逐页手改：

- 浅底容器（`.chip / .qc-head / .eg-box / .formula / .tree-box / .tip-bar / .tab-num …`）→ `var(--surface)`，并连带容器内文字回到 token；
- 硬编码深字（`.cell-main / .v / .tn-name / .rr-name / .mono …`）→ `var(--ink)`，次级说明 → `var(--ink-2)`；
- Element Plus 分页 `#606266` 灰字、蓝底白字 → token；
- `.qr-box` 二维码容器保留白底（扫码功能性例外）。

### 目检才抓到的缺陷（数值断言全绿之后）
1. 结算页两块**浅色渐变**白卡（`.formula`、`.eg-box`）——`background-color` 透明导致初版白块审计漏掉。先修审计口径（同时检查 `background-image` 渐变），再补 CSS，一次清零。
2. 深色下表格副标题、溯源批次字段、质检报告等小字几乎不可见 —— 由低对比审计批量抓出 13 类，集中规则清零。
3. 三档同页截图逐张比对，确认「只有明暗变，骨架不变」。

## 5. 使用与遗留

- 顶栏「外观」选一次即全站生效并记住；默认浅色。登录页不显示选择器，但会读取同一份全局设置。
- 三档只改颜色，**不会再出现字体、导航、密度跳变**；明暗差异仍在（浅色 ↔ 深色），但这是同一产品的浅/深色模式，不是换系统。
- 遗留：`html[data-mode]` 的 night 适配层是「兜底规则」而非彻底消除业务 view 里的硬编码色；新增页面若引入浅色专用色值，验收门禁会抓出来，在适配层补一条规则即可全域生效。
- 表头排序仍是 DOM 层、只排当前页（与本次改动无关）。
