## 一、为什么现在"AI 味"重：根因不是配色

| 现象 | 证据位置 | 本质 |
|---|---|---|
| 全站只有一套 CSS 变量，没有设计语言 | `frontend/src/styles/tokens.css:1-65` | 只是把 Element Plus 默认主题刷成 `#16a34a`，没有排版层级、组件语义、动效规范 |
| 模板化无信息装饰 | `global.css:122-131`（每张统计卡右上角径向渐变光晕）、`:91-97`（卡片标题渐变竖条）、`:427`（头像渐变） | 装饰不承载信息，是 AI 生成后台模板最典型的特征 |
| 30 个页面同一套骨架 | `frontend/src/views/` 28 个 view | 一律「page-head → 4 张 stat-card → filter-bar → el-table」，页面之间没有节奏差异 |
| 交互只有 hover 和 fade | `AppLayout.vue:83-87`、`global.css:413-416` | 无命令面板、无行内操作、无批量条、无骨架屏、无实时筛选、无提交防抖、无键盘导航 |

**结论**：这是设计系统缺失，不是改几个色值能解决的。因此下面给的是 3 套**完整设计系统**（色板 / 字体 / 组件语言 / 导航形态 / 交互规范 / 落地成本），不是 3 张色卡。

## 二、方案 A · 田埂（Organic Editorial）

**定位**：把「农产品溯源」做成一本可以翻阅的纪实刊物——有产地、有温度、可信。

| 项 | 规格 |
|---|---|
| 色板 | 纸白 `#F6F2E9`、墨绿 `#2F5D3A`、陶土 `#B4633C`、麦芽 `#B98F3E`、墨字 `#20372A` |
| 排版 | 中文衬线大标题（宋体系）+ 衬线正文 + Georgia 数字；字号层级拉开，大留白 |
| 组件 | 2px 近直角、**零阴影零渐变**、1px 细线分隔；统计卡用左侧 2px 色条代替光晕 |
| 导航 | 218px 纸色侧栏，菜单带 01–08 编号，激活态用下划细线 + 陶土圆点 |
| 主视觉 | 真实农产摄影（竹篮时蔬 / 亚麻 / 纸纹），登录页左图右表单 |
| 交互 | 滚动揭示、溯源时间线节点展开、筛选胶囊、卡片微位移、页面左滑淡入 |
| 适配 | 答辩演示、对外展示、品牌区、溯源查询页 |
| 成本 | **中** — 衬线字体 + 图片资产 + 约 3 套组件重做 |
| 风险 | 表格密集页（订单、用户、日志）会显得松散，需要单独做紧凑变体 |

---

## 三、方案 B · 枢纽（Ops Console）★ 推荐日常主力

**定位**：面向四角色的高频操作中台。把「缺少交互性」这条正面补齐，而不是只换皮。

| 项 | 规格 |
|---|---|
| 色板 | 冷白 `#F6F8FC`、靛蓝 `#2F5BEA`、石板 `#0F172A`、青 `#0E9F9B`；**单一强调色** |
| 排版 | Inter / 系统无衬线，8px 栅格，紧凑字号，`tabular-nums` 数字对齐 |
| 组件 | 6–10px 圆角、1px 细边框、极轻阴影；卡片更薄，信息密度更高 |
| 导航 | **70px 纯图标窄栏** + 顶部 `⌘K` 命令栏；释放横向空间让表格多显示 2 列 |
| 主视觉 | 冷白等距网格 + 靛蓝折面，无文字无装饰 |
| 交互 | `⌘K` 命令面板、实时搜索、状态 chip 筛选、表头排序、行 hover 操作、勾选批量浮动条、分页、骨架屏、toast、键盘导航、提交防抖 |
| 适配 | 四角色日常作业、审批、表格密集页面（本项目 28 个 view 中约 18 个是表格页） |
| 成本 | **低** — 沿用 Element Plus，主要是重排 + 补交互 + token 重映射 |
| 风险 | 视觉个性最弱，容易被认为"还是个后台模板"；建议登录页/溯源页借用 A 的材质 |

## 四、方案 C · 夜航（Dark Ops）

**定位**：深色数据驾驶舱。实时、沉浸，但**克制**——发光只用于状态点与数据高亮，不做赛博霓虹堆砌。

| 项 | 规格 |
|---|---|
| 色板 | 深墨 `#0A1320`、面板 `#15253A`、青蓝 `#3DD9C0`、琥珀 `#F5A524`、亮字 `#E9F2F9` |
| 排版 | 无衬线 + 大号等宽数字；面板靠**明度分层**而非玻璃模糊 |
| 组件 | 8–14px 圆角、细网格背景、极细发光描边；状态灯带脉冲 |
| 导航 | **取消侧栏**，顶部横向导航 + 实时时钟 |
| 主视觉 | 深墨等高线 + 青/琥珀数据节点与链路曲线 |
| 交互 | 数字滚动、图表 hover 十字线、告警脉冲、链路流动线、时间范围平滑切换、卡片展开 |
| 适配 | 管理员驾驶舱、大屏投放、监控汇报 |
| 成本 | **高** — 深色 token 全量重映射 + ECharts 主题适配 + 打印/投屏另配浅色 |
| 风险 | 长时间办公易疲劳；表格密集页在深色下可读性需要逐页验收 |

> 对比度已实测：A 11.45:1、B 16.79:1、C 16.45:1，均满足 WCAG AA（预览页右侧面板实时显示自检值）。

## 七、交互补强清单（三套方案共有的底线）

不管最终选哪套，以下条目都会进重构范围，专门解决"缺少交互性"：

1. `⌘K` / `Ctrl+K` 命令面板：直达任意页面与常用操作
2. 表格：实时搜索、状态筛选、表头排序、行内快捷操作、批量选择浮动条、分页状态
3. 反馈：骨架屏、按钮 loading、操作 toast、错误态空状态、防重复提交
4. 导航：键盘可达、焦点可见、当前位置高亮、面包屑
5. 动效：页面转场、卡片 hover、数字滚动、图表十字线；`prefers-reduced-motion` 一键降级
6. 表单：即时校验、焦点态、密码显隐、错误定位

## 八、落地约束（选定后重构时严格执行）

- **内容保真**：沿用现有 28 个 view 的业务 DOM 与数据契约，只换外壳与样式；逐页做「重构前/后纯文本比对」，不允许重敲业务字段（经验库 L-020）。
- **不破坏已修好的鉴权**：角色身份取自 store/service、四角色共用组件必须走 `/api/common/*` 公共前缀；受控资源不要交给 `<img src>`，沿用 base64 内联（L-023）。
- **不回退测试门禁**：重构后必须重跑 `mvn test`（当前 66 用例）、`tools/review_system_test.py`（69 项）、`tools/review_pw_check.cjs`（30 路由巡检 + 控制台 4xx 判据）。
- **主题变量只在 `html[data-scheme]` 上定义**，不在 `body` 重定义；深色方案逐页做文字/底色对比度实测，不用截图猜（L-021）。
- **原始版本保留**：`backup_before_fix_2026-11-09/` 与本轮设计稿均不覆盖，重构输出到可对比的新版本。
