# 我以四个角色的身份用了一遍：哪里顺手，哪里憋屈

日期：2026-11-10　范围：农校直供系统（管理员 / 农户 / 采购员 / 质检员）

---

## 0. 这次不是"看页面"，是"干活"

前几轮的体检都是量指标：字号、溢出、控件数、控制台报错。那些只能证明**页面规整**，证明不了**活能干完**。

这次换了方法：给自己派活，按现实中这几个人早上的真实处境，把事做完。

| 角色 | 我给自己派的一天 | 具体动作 |
|---|---|---|
| 王管理（管理员） | 周一 8:50，食堂中午要开饭 | 看今天有几件事等我 → 批一个新农户 → 找一单超时订单 → 审一笔结算 → 处理一条食安预警 → 查"谁改了王丰收的信用分" → 导出一份订单表给领导 |
| 王丰收（农户） | 早上 7:30，刚摘完菜 | 把今天的大白菜挂上去（137kg / 2.11 元）→ 看有没有新单要接 → 看这个月挣了多少 → 弄明白信用分为什么掉 |
| 李建国（采购员） | 早上 8:00，备明天的菜 | 搜"白菜"找货 → 下单 137kg → 核对总价 → 收货时改实收数量（短斤少两）→ 入库 → 评价 |
| 赵质检（质检员） | 早上 9:00，菜到了要抽检 | 看今天几单 → 指定某一单录质检 → 判定达标 → 发起配送 → 扫码交付 |

然后我把这一整条链**自己跑了一遍**：发布货源 → 采购下单 → 农户接单 → 发货 → 质检 → 配送 → 入库（少收 7kg）→ 结算 → 评价。

结论先给：**这系统不是"长得难看"，是"干到一半没路了"。而且拦住我的地方，全在屏幕上——不在功能里。**

---

## 1. 让我卡住的地方（按严重程度）

### ① 质检员根本进不去质检录入 —— 唯一的下一步入口在屏幕外

以赵质检身份登录 → 我的任务 → 5 条待检任务，表头是「批次号 / 产品 / 供货农户 / 数量 / 收货食堂 / 状态」。

**「操作」列不见了。** 不是隐藏，是被挤出可视区 144px。卡片只有约 540px 宽，7 列 min-width 加起来 856px，Element Plus 的横向滚动条是浮层样式，不动鼠标根本不显示。

结果就是：我盯着一张"看起来很正常"的表，找不到任何可以点的东西。这一条足以解释"说不出来为什么难用"——**不是我笨，是入口真的不在屏幕上。**

同类问题还有 4 处：管理员结算页操作列被裁掉 8px（"凭证"两字被切一半）、订单监管、食安预警、配送任务的操作列都没做固定。

### ② 点了「质检合格」，以为提交了，其实只是选了个单选项

质检页上半部分是六项检测（农残、重金属、含水率、新鲜度、重量复核、冷链温度），下半部分两个大卡片：「质检合格」/「不通过」。看着就像"点这个就完事"。

**真正的「提交质检」按钮在 1230px 处，而视口只有 900px。** 我点完「质检合格」等了三秒，什么都没发生，页面也没提示"别忘了点提交"。

更别扭的是：从菜单直接点「质检录入」，载入的是 **4 天前的老单**（`records.find(status===30)` 取第一条）。我明明刚被告知"有货到了"，系统给我一张四天前的单，而且页面上没有"换一单"的地方。

### ③ 配送任务只能干一趟，剩下的看得见、点不动

配送页上方是"当前配送任务"详情，下方一张表列了 4 趟。但表里每行只有「轨迹 / 详情」，**没法把那一趟切成"当前"**。

我只能处理后端替我挑的那一趟。另外 3 趟在表里明明白白摆着，我点不动。系统还给了「开始配送 / 扫码交付」大按钮，但那是给"当前"那趟的——我甚至不确定点下去操作的是哪一票货。

### ④ 入库页一整套表单全灰，却不告诉我为什么

我拿着订单号 DD202611100330 去入库，实收数量、质检结果、确认入库——全 disabled。页面上一个字都没说原因。

实际上是因为这单还在"待质检"。但这个理由得我自己去别的页面推。**禁用而不给原因，用户只会判定"系统坏了"。**

### ⑤ 管理员查"谁改了农户信用分"，查不到

系统有 251 条信用变动记录，但操作日志 12866 条里**含"信用"的 0 条**。因为 `CreditService.change()` 只写了 `credit_score` 表和主表分数，从来没调 `LogService.record()`。

审计链在最关键的"谁动了这个农户的经营资格"这一环断了。而且日志表只有「操作人 / 功能模块 / 操作内容」，没有「操作对象」列，只能靠内容字符串里有没有那个名字。

### ⑥ 农户登录进去，六个状态标签全是 0

王丰收名下 30 单：25 单已完成、5 单已结算。**待接单 0、已接单 0、待质检 0、配送中 0、待结算 0。**

我作为农户想体验"接单、发货"，一个能点的都没有。这不是 bug，是种子数据只造了"历史账本"，没造"正在发生的事"。四个角色里有两个（农户、质检）进去基本无事可做——**用户会以为功能没做。**

## 2. 顺手的地方（这些确实做得好，不用改）

说清楚，免得改坏：

- **顶栏「待办」是真入口**，不是装饰角标。点一下直接落到该角色要处理的页面（管理员→食安预警、采购→入库、质检→我的任务）。
- **「动态」面板是真实时**。我在采购员那边确认入库，管理员这边的动态里立刻出现"李建国 确认了收货入库 18:42"。跨角色反馈是真的。
- **Ctrl+K 命令面板能用**，列得出全部页面，不是摆设。
- **入库页的实时算账**：改实收数量，损耗数量、损耗率、实际结算金额当场重算；损耗率超阈值会红字提示"确认后将自动生成结算单并扣减农户信用分 −2"。这页是全系统做得最扎实的。
- **结算页把公式摊开给你看**：订单金额 − 损耗扣款 − 质检扣款 = 实付金额，还配了一条真实单据的算例（400kg×1.80=720，损耗 20kg 扣 36，实结 684）。审钱的时候不用猜。
- **农户工作台会说话**："王丰收，早上好！丰禾农业合作社 · 今日暂无待处理订单，请保持货源充足、及时响应新订单"。空状态给了下一步该干嘛。
- **质检页本身设计得专业**：六项指标带国标值（农残 ≤0.05mg/kg、叶菜含水率 ≥95%）、结论区写明后果（合格→生成二维码放行；不通过→整批驳回、扣 5 分）。只是入口和提交被上面两个问题挡住了。

一句话：**页面质量不低，是"操作链路"没走通。** 这也解释了为什么"说不出来哪里难用"——每一页单看都像样，连起来就断。

## 5. 还没改的（如实说）

1. **表格行内仍是多个文字链**，没做成"主操作按钮 + 更多"。质检录入那条我加粗带箭头了，但全站没统一。
2. **配送任务默认选中哪一趟仍然由后端决定**（`latestActive()`），只是现在能手动换了。理想是"待发车优先、按交付时限排序"。
3. **操作日志没有独立的「操作对象」列**，靠内容字符串携带农户名和单号。要真正做审计，应该加 `target_type / target_id` 字段。
4. **产品档案里有重复品名**（"大白菜"同时存在 id=1 和 id=11），货源和订单会挂到不同 id 上。这次没动，属于数据治理。
5. **菜名/规格这类字段没有统一字典**，靠自由文本，长期会脏。
6. 这次只覆盖 4 个角色的主路径，**异常分支**（拒单、整批驳回、超温报警、账号停用中途被踢）只验了接口和跳转，没逐个走 UI。
