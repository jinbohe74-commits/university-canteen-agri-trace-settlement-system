## 二、关键字段与约束

**orders（订单）**
- `status`：10 待接单、20 已接单、30 待质检、40 质检通过、41 质检不通过、50 配送中、60 已送达、70 已入库、80 待结算、90 已结算、100 已完成、99 已取消
- `version`：乐观锁版本号，状态流转 SQL 为 `UPDATE orders SET status=?, version=version+1 WHERE id=? AND version=?`，影响行数为 0 时抛出并发冲突
- 索引：`uk_order_no`、`idx_farmer`、`idx_canteen`、`idx_status`、`idx_create_time`
- 外键：`farmer_id → farmer(id)`、`canteen_id → canteen(id)`

**settlement（结算单）**
- `total_amount = 下单数量 × 成交单价`
- `loss_deduction = (下单数量 − 实收数量) × 成交单价`
- `actual_amount = total_amount − loss_deduction − deduction(质检扣款)`
- `order_id` 唯一，保证一单一结算

**trace_record（溯源）**
- `batch_no` 唯一：`PC + yyyyMMdd + F + 农户ID(4) + 产品ID(4) + 随机数(3)`
- `hash`：对 `批次号|农户ID|产品ID|质检结论|数量|质检时间` 计算 SHA-256（64 位十六进制），用于业务完整性核验
